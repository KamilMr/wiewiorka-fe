# Agent Instructions

## Pull requests and review

- Write concrete PR titles and descriptions in English. Keep routine descriptions
  around 100–200 words; simple changes need less.
- Explain the problem, what the change achieves, and why it is needed. Add a
  brief before/after example when helpful.
- Use the PR template. Point to the key files or behavior to review and explain
  important tradeoffs. Skip unnecessary detail for trivial changes.
- Report actual checks, exact commands, and results. State failed, blocked, or
  unrun checks and why. Give remaining manual steps with expected results;
  never present suggested tests as completed work.
- Describe the final diff, target the intended integration branch, and mention
  dependent PRs or limitations that affect review.
- When asked to follow up, read the latest review comments and answer each
  question in its original thread. Use plain English unless asked otherwise.
  Explain the behavior and reasoning with a concrete example or file reference
  when useful, and define unfamiliar terms.
- A question requests explanation, not automatically a code change. For requested
  changes, explain the fix and verification. Support disagreements with evidence.
- Leave the PR open for the reviewer. Merge only when explicitly authorized.
